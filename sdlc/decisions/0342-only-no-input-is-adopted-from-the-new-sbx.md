342. **Only `--no-input` is adopted from the new `sbx` features (2026-11-22, the user's choice, planning round 1 of milestone 6):** sbxm makes most `sbx` prompts fail by closing stdin, but `create` and `run` keep it open, so a new prompt there could hang an unattended task. Milestone 6 passes `--no-input` on the unattended calls (task, loop and `sbxm run` workers), so a new prompt fails at once with the command to run. The other new features (`sbx df`, `run --rm`, the `sbx port` commands, the new settings) are logged as gaps with triggers, not built. Adopting none was the other option, not chosen: the hang risk would stay for the first unattended run on 0.54.
