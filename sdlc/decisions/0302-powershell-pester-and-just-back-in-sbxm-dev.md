302. **PowerShell, Pester and `just` are back in the `sbxm-dev` profile, installed at template build (2026-11-07, the user's answers on issue #455; supersedes the tooling part of [183]):** decision 183 took them out because every sandbox paid about 2 min 45 s of setup for tools the gates never used (`cargo install just` about 90 s, PowerShell and Pester about 11 s), and it named a prebuilt template as the way to remove that time. Templates exist now (milestone 3, strict, decision 200): the install runs once per template build and a sandbox made from the template starts with the tools. The cost of leaving them out showed on #327 (PR #454): the worker hit `pwsh: command not found` 5 times, the reviewer could only read the Pester tests, and a relative-path bug reached the PR untested. Versions are pinned to the host's (PowerShell 7.6.9, Pester 5.5.0, `just` 1.58.0). The hosts `packages.microsoft.com`, `www.powershellgallery.com` and `cdn.powershellgallery.com` go back into `[network] allow`, which a strict template uses only while it is built; `[template] allow` stays empty, so a worker's sandbox reaches none of them. The rest of #455 builds on this: a Pester gate that runs on every task, whatever the change touches (changed by the user on 2026-11-07: the first version ran only when a change touched `scripts/`, but finding the task's base reliably cost more than the 10-13 s the Pester tests take in the template), and Pester tests fixed to pass on Linux as well as Windows. CI still doesn't run Pester; that gap's trigger is a script bug reaching `main` that the Pester tests on Windows would have caught.
