### Patterns (two or more instances)

Status is judged in windows 2 and 3.

1. **Untrusted agent or contributor input crossing into the host** (13 findings in 7 records): links read
   through a profile (M1 S1), inherited git config running a host filter (M2A-1), a raced bundle check and an
   unchecked PR fetch (slice 5 S1, S2), a committed `cargo.cmd` (slice 7 G7-5), agent commits pushing
   `.github/workflows` (slice 10 M2), agent text in the PR body (slice 10 S3, PR #57 R2-S3), links in
   `.sbxm-task` (R1-M1), a partial gate tier authorizing review (R2-M1). Expected in a project whose goal is
   isolation, but each review found a new path, not a repeat of a fixed one. Status: open (#59 and #244 come later).
2. **A write before the refusal** (6 findings in 5 records): M1 M1 and M2, slice 10 M1, M2b end-to-end S-2,
   R1-M4, R2-S5. Status: to check (`task::pipeline` now states "every refusal comes before the first
   write"; when that rule arrived is unknown).
3. **Should-fix findings parked for "the end of the milestone" came back as findings** (4 instances): the slice
   reviews' G7-3, G7-4, slice 10 S3 and S5 came back in PR #57 round 2 as R2-M2 (raised to must-fix), R2-S1, R2-S3
   and R2-S4. Status: to check (should-fix findings have been filed as issues since decision 90; #58-#60 are still
   open).
4. **The worker's sandbox, the gates and Windows were three different environments** (G2, G9, G10, G20, the
   M2b end-to-end M-1 (no `~/.cargo/bin` on the gates' PATH), three platform findings (slice 5 S3, G7-3, R2-M2),
   PR #69's and #103's gate failures in review that the worker's gates had passed). Status: to check (CI on Windows
   from 2026-10-05; templates in milestone 3).
5. **Disk space stopped work** (C: at 0 GB three times on 2026-10-02, after which `sbx` answered 401; spike S11
   stopped on a full disk; E: down to about 4 GB; G18, G19; a disk junction to H: broke the claude agent and was
   reverted). Durations unknown. Status: to check (#210's disk check, decision 194, came 2026-10-13).
6. **Reruns of a whole task step for one failure** (#63's 3 restarts, at about 1.5 h each by G25; #81's 3 failed
   creates; PR #69's 3 failed review runs; G16, G17, G25: no way back into a task but a full restart). Status: to
   check (decision 169, then `task resume`, #118, came later).
7. **The user stepped in by hand for routine steps:** GitHub permission popups (at least 2 on 2026-10-01), pushes
   until 2026-10-01, freeing disk (3+ times on 2026-10-02), asking twice whether a long job was still running
   (`notify-on-long-jobs`), copying review results, running task steps from their own terminal (G24). Status: to
   check.

Single instances, not patterns: a commit that didn't compile (M2A-3), a config section accepted and ignored
(M2A-2).

### User rules made in window 1

Kept as working rules since: short messages and one question at a time; flag over- and under-specifying; a PR for
every change; warn on complexity; process changes as experiments (2026-10-01); progress as X of Y and at most 3
sessions; a known binary for long jobs; workers install nothing; optimize just in time; notify when long jobs end.

### New patterns in window 2

8. **Long review loops are failure-path loops.** Ten tasks took more than 3 rounds (in-task plus PR): #202 (13),
   #207 (9), #120 (8), #194 (7), #90 (7), #123 (6), #198 (6), #195 (6), #118 (5), #201 (4). In #207, #202, #194,
   #120 and #118 the findings were failure paths of the change's own recovery: a rerun after a failed step, a link,
   a record that disagrees with its folder, output failing midway. The edge-case checklist experiment started on
   2026-10-14 for this.
9. **Model limits stopped runs:** the 5-hour usage limit (#121's three worker runs, PR #208's review), Antigravity
   credits (#118's review, 402), a reviewer at capacity (#201).
10. **Waiting outweighs working:** #202 used about 2h16m of machine time over 14.5 h (gaps of 1h13m, 1h50m, 9m and
    about 9 h overnight for an approval); G49 counts about 3 h of stops and waits. Other tasks: unknown, since
    no stop-to-next-command time is recorded.
11. **Size didn't predict effort,** on 4 data points: #202 (M) took 13 rounds, #195 (L) 6, #201 (M) 4, #210 (M) 3.
    Too few to judge; window 3 adds more.

### User rules made in window 2

A fork stops after opening its PR; file an environment bug only when it happens again; a reviewer judges the change
only, and after 2 rounds with must-fix the user decides; no Antigravity until asked; tick review boxes after hand
fixes; push to a PR branch without asking and mark drafts ready; decisions go in the issue body; no self-edits of
permissions; no parallel build reviews; titles next to numbers.
