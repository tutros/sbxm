## Should fix

### M3S7-1 - `template rm` racing the end of a `template build` of the same key can delete the new record and orphan the new image

**Where:** `src/commands/template_rm.rs:33-61`, `src/commands/template_build.rs:105`, `src/commands/template_build.rs:119-134`, `src/commands/template_build.rs:533`
**What happens:** `template rm` takes no lock. `template build` holds `<key>.build.json` (decision 212) but `rm`
never looks at it. One interleaving: rm loads the old record `{tag: T1}` (line 33); the build saves its new record
`{tag: T2, previous: [T1]}` (template_build.rs:533); both then call `sbx template rm T1`; rm's succeeds and the
build's fails, so the build keeps `previous == [T1]` and skips its second save (line 128); rm then deletes
`<key>.json` (line 61). Result: image T2 (1.3-2.6 GB) exists and no record names it, which is exactly the leftover
decision 224 removes on failure and decision 226 defers detecting. The window is rm's own duration (seconds: two
`sbx` calls) lining up with the last seconds of a minutes-long build, so it needs bad timing; the more likely
overlap (rm during the build's run) ends cleanly: the build re-adds `{T2, previous: []}` after finding T1 gone.
Not shown by a test: it needs two processes and an interleaving hook the `FakeBackend` doesn't have.
**Why it matters:** decision 212's lock exists so two commands that change one key's record and images don't race;
`rm` is the second such command and isn't covered. Not must-fix: no failing input without a contrived timing, and
nothing is deleted that is in use; the loss is disk space (should-fix, hardening of a narrow race, like the accepted
decision 227).
**Fix:** smallest: before loading the record, refuse while `<key>.build.json` exists: "a template build of KEY is
running or was interrupted (PATH); wait for it, or delete PATH if no build is running". A build started after rm's
check can't reach its save within rm's seconds. Fuller (if wanted): move `Build::lock` into `template.rs` and have
`rm` take the same lock with `create_new` for its duration, without the leftover cleanup.
**Size:** S: one check in one command, one test.
**Depends on:** none known
**Acceptance criteria:**
- [x] With `<base>/.sbxm/templates/default-claude.build.json` present, `template rm default` fails naming that file, `FakeBackend` logs no `template-rm` and the record still exists
- [x] A test covering it fails before the fix and passes after (`tests/template_ls_rm.rs`, e.g. `refused_while_a_build_of_the_key_holds_the_lock`)
- [x] `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` pass
- [ ] Docs updated where behavior users see changed (README `template rm` text in slice 11), or "no user-visible change" — not done: README's `template rm` text comes with slice 11

### M3S7-2 - The in-use check passes when `.sbxm/tasks` exists but can't be read

**Where:** `src/task/record.rs:846-855`, `src/template.rs:107`
**What happens:** `template::users` reads tasks through `record::load_all` -> `task_folders`, which does
`let Ok(entries) = fs::read_dir(tasks_root(base)) else { return Ok(Vec::new()) };`. Any `read_dir` error
(permission denied, `.sbxm/tasks` being a file), not only "not found", is treated as "no tasks", so `template rm`
removes a tag a task records. The other failure paths do fail closed: an invalid `state.json` (state.rs `load`), an
unreadable or invalid `task.json` (`record::read`), and an error reading a `.sbxm` entry all propagate, and
`refused_when_a_task_record_cannot_be_read` covers the `task.json` case. The swallow is older than this slice
(`task_folders` came with `task rm --merged`), but this slice makes it the guard of a deletion.
**Why it matters:** the slice row's guard ("its in-use check over `state.json` and every `task.json` is the guard")
and decision 205(b); decision 225 already treats "can't check" as "in use".
**Fix:** in `task_folders`, return `Ok(Vec::new())` only for `ErrorKind::NotFound`; propagate the rest with
`cannot read <path>`.
**Size:** S: one function, one test.
**Depends on:** none known
**Acceptance criteria:**
- [x] With `.sbxm/tasks` replaced by a file, `template rm default` is refused naming `.sbxm/tasks`, and no `template-rm` is logged
- [x] A test covering it fails before the fix and passes after (`tests/template_ls_rm.rs`)
- [x] `task rm --merged`'s tests still pass (it shares `task_folders`)
- [x] `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` pass
- [x] Docs updated where behavior users see changed, or "no user-visible change": no user-visible change beyond the new refusal

**Where:** `src/commands/template_rm.rs:41-57`, `src/commands/new.rs:113`, `src/commands/new.rs:160-186`
**What happens:** `rm` checks users, then removes. A `new` that chose the tag (new.rs:113) and creates its sandbox

already rejected in 227. Option b: record the tag in `state.json` before `create` (larger change, touches `new`'s
rollback).
