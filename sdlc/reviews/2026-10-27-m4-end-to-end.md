## Gaps found

Logged as G67-G69 in `sdlc/evals-workflow-notes.md`.

- **`sbxm-dev` can't build in the cloud:** its first install step (`apt-get install build-essential ...`) exits 100
  in the cloud image, so `sbx --cloud create` fails in the kit. sbxm handled it as designed (refused, no task
  folder, no sandbox left). The profile's apt hosts or the cloud image's sources likely differ; not investigated.
  Trigger: the first real cloud task on this repo.
- **`run.log`'s cloud lines are written late:** the create and removal lines land when the phase ends, stamped with
  that time and stage (the worker's create logged as `[gating]`, a reviewer's create and removal at the same second
  as `[ready]`). The sandbox entries in `task.json` hold the true times. Trigger: anyone reading `run.log` for timing.
- **The logged-out refusal says `sbx login` twice:** `sbx`'s own `try: sbx login`, then sbxm's "if you're not
  logged in, run `sbx login`". Cosmetic.
