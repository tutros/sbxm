# Spike S12: the Jev API against a real token

Run 2026-10-03 on `sbx` 0.46.0 (Windows host) with the pinned build `sbxm` commit `f243288`, in one throwaway sandbox
(`sbxm-s12-jev-claude`, egress `api.typesafe.ai` only, a secret scoped to that sandbox). Question (from `sdlc/jev.md`):
do the endpoint, the Bearer header and the answer shapes in Jev's docs hold against a real token, and what do the
errors, the token cost, the run-to-run variation and the model naming look like?

**Verdict: the docs hold, with five corrections that change the draft issue (section "Corrections to the slice 14a
draft").** About 40 calls were made; none was rate limited. The token reached the call through `sbx secret set-custom
--command` exactly as spike S9 predicted, and the real secrets were untouched.

## Token handling (the user's rule)

The token sat in a file the user created. It was **not opened, read or printed** by the assistant; only its name and
size were looked at. A helper script outside any workspace prints it, and `sbx secret set-custom --sandbox <name> --host
api.typesafe.ai --env JEV_API_KEY --placeholder <p> --command <helper>` stored the source (the listing shows the helper's
path and `refresh: on-demand`, no value). The sandbox's environment held only the placeholder. Cleanup: the sandbox and
project were removed with `sbxm rm --purge`, the scoped secret was gone afterwards (`sbx secret rm` answered "no custom
secret found": removing the sandbox had removed it; S9 had seen it orphaned, so check this again), and `sbx secret ls
--json` was byte-identical before and after.

Limit of this record: because the token was never read, absence of the token from the saved request and response files
was not checked by searching for it. Those files contain the placeholder name at most, and no response echoed a header.

A mistake worth keeping: the first four calls returned 401 because the probe script put `$JEV_API_KEY` inside single
quotes in the sandbox shell, so the literal text was sent. The helper had also been rewritten before that was found, so
it is **not known** whether the first helper (a plain `type` of the file) would have worked.

## Not tested

429 and 529 behavior (no rate limit was reached, and the API was not hammered); HTTPS redirects; concurrent calls;
`state` as an array; Score questions with more than 3 levels; whether answers agree with the LLM judge or with humans
(the calibration that decides whether Jev can be the primary classifier); the exact size limit; and how stable the
answers are over days or across model versions (only `jev-1.13.0` was seen).

## Corrections to the slice 14a draft (`sdlc/specs/jev-evaluator-14a.md`)

1. **`model` is required in every request.** The config default `jev-latest` is sent explicitly; record the **response's**
   `model` (`jev-1.13.0`) in each pair's `evals.json` and in `run.json`, so a result names the version that produced it.
   Offer pinning (`model = "jev-1.13.0"`) for reproducibility.
2. **Error handling:** the draft said "422 is recorded with the response's message". There are three shapes: 401 and
   400 carry `detail.error_type` (plus a `message` except for `max_tokens_exceeded`), 422 carries a list. A 422 body
   **echoes the whole request** (`input`), which here includes the contestant's answer and diff: never write a raw error
   body to a result, a log or a warning; keep `error_type` or the list's `loc` and `msg` only.
3. **Oversize is a 400 `max_tokens_exceeded`, not a 422**, with no token count, so the estimate must stay on our side.
4. **Token estimate:** 1 token per 3 characters (the draft) is safe for code and conservative for prose (about 4.0). It
   is slightly optimistic for the first 1,000 characters of a diff (3.02), so keep the 28k cap and the per-request
   overhead of about 295 tokens plus about 50 to 70 per extra question in the budget.
5. **Noise:** Score answers vary slightly between identical calls. Record `confidence`, and treat one call as a sample.
   Whether to average several calls is a design question for the user (cost is not the constraint: see `sdlc/jev.md`).

Also confirmed unchanged: Noul and Score shapes and their mapping (`score / (levels - 1)`), the token never leaving the
host except as a header the proxy swaps, a scoped secret created before its sandbox, and `usage` in every success.
