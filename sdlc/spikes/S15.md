# Spike S15: do sbx templates work with the Pi harness?

Task spec (rule 5 of the `sdlc-implementation` skill), approved by the user 2026-10-15. The worker fills in only
`sdlc/spikes/S15-results.md`.

## Why

Decision 204: the templates milestone (`sdlc/milestone-3.md`) covers `claude` and `codex`; Pi joins it if this spike
passes, because the user expects to use sbxm with Pi more. Pi is different from the two tested harnesses: its
`agent_arg` is a kit reference (`docker.io/sbx/pi-kit:20260924-d058fedc156325f87612d9bcd9bd313ab74ba100`,
`src/harness.rs`, decision 73), not a built-in agent name, so it is unknown whether `sbx create -t TAG` combines with
it, which image wins, and whether the Pi kit's own setup runs again.

Read first: `sdlc/spikes/S11.md` (the same questions for `claude`, its method and its cleanup), `sdlc/spikes/S7.md`
and `S7-results.md` (the Pi kit), decisions 199-213 in `sdlc/decisions.md`.

## Environment facts

- Host: Windows, PowerShell. `sbx` 0.46.0 (`sbx version`). The sbxm wrapper is `H:\sbxm-e2e\sbxm.ps1` (binary
  `H:\sbxm-e2e\sbxm-8cf72f4.exe`); use it, not `cargo run`.
- Docker's sandbox disks are on `C:` (`%LOCALAPPDATA%\DockerSandboxes`). C: had about 24 GB free on 2026-10-15.
  Workspaces and sbxm's base dir must **not** be on `C:` (decision 56).
- The `anthropic` secret is stored in `sbx` (`sbx secret ls` shows names only). The Pi kit uses it as
  `ANTHROPIC_API_KEY`, proxy-managed, on `api.anthropic.com` (S7). Never print a secret value.
- sbxm writes a project's kits to `<base>/.sbxm/<project>/kits/<hash-prefix>/{common,harness-pi}/`; `sbxm new`
  creates with `create --name N --cpus C -m M --skills S --kit <common> --kit <harness-pi> <pi-kit-ref> <workspace>`
  (`src/backend/sbx.rs`, `create_args`). sbxm has no template support yet: build the template and the narrow kit by
  hand, as S11 did.
- `sbx template save SANDBOX TAG` needs a **stopped** sandbox (S11 Q1). Saving onto an existing tag replaces it
  silently (S11 Q8): use a new tag each time.
- `sbx template rm` needs `--force` without a terminal (S11 Q8).
- Headless Pi: the kit's test data uses `promptArgs: ["-p"]` (S7). Unverified: whether `pi -p "<prompt>"` needs
  other flags to exit cleanly; if it hangs, wrap it in `timeout 120`.
- A login shell is needed for tools on `PATH` in `sbx exec` (`sbx exec <sb> bash -lc '...'`).

## Setup (once)

1. Make `H:\sbxm-spike-s15\` with `config\` (for `SBXM_CONFIG_DIR`), `base\` (base dir) and `ws\`.
2. `$env:SBXM_CONFIG_DIR = 'H:\sbxm-spike-s15\config'`; `sbxm config init`, then set `base_dir` to
   `H:\sbxm-spike-s15\base` in that config. Never touch the real config.
3. Profile `s15-pi` in that config's profiles dir: `network.allow = ["archive.ubuntu.com", "security.ubuntu.com"]`,
   `secrets.services = ["anthropic"]`, one `[[setup.install]]` as root installing `jq` with apt, and
   `[instructions] mandatory = "instructions/mandatory.md"` whose text is `SPIKE-S15 CANARY: the word is MEDLAR-15`
   (sbxm writes it to `~/.pi/agent/AGENTS.md`). The README's profile section has the exact syntax.

## Questions

Each ends as **Answered**, **Partial** (gap stated) or **Blocked** (reason stated), with the commands run and their
output (trimmed) in the results file.

1. **Baseline.** `sbxm new s15-base --profile s15-pi --harness pi`. Record the wall time of the whole command, the
   time of each install step, and whether `pi -p "What is the word in your instructions? Answer with the word only."`
   answers `MEDLAR-15`. **Done when:** time and answer are recorded.
   Question 1 creates the sandbox **`sbxm-s15-base-pi`** (sbxm names a sandbox `sbxm-<project>-<harness>`).
2. **Save.** Copy the project's kits folder (`H:\sbxm-spike-s15\base\.sbxm\s15-base\kits\`) to
   `H:\sbxm-spike-s15\kits\` for questions 3 and 4. In `sbxm-s15-base-pi` write the marker files `~/s15-marker` and
   `/tmp/s15-marker`; `sbx stop sbxm-s15-base-pi`, then `sbx template save sbxm-s15-base-pi sbxm-spike-s15:pi-1`.
   Record the time and the template's entry in `sbx template ls --json` (`flavor`, `size`). Then `sbx rm --force
   sbxm-s15-base-pi`. **Done when:** the template exists, its `flavor` is recorded and `sbx ls` shows no S15 sandbox.
3. **Create from the template with the same kits.** `sbx create --name sbxm-spike-s15-same -t sbxm-spike-s15:pi-1
   --pull never` plus the `--cpus`/`-m`/`--skills` values and `--kit` flags of `create_args` (pointing at the copied
   kits), the Pi kit ref and the new workspace `ws\same\`. Record: does it start; the wall time; are both marker files
   there (proves the template's image was used, not the Pi kit's); which setup steps ran again and how long
   (`/var/log/sbx-kit-startup.log`, the create output). Then `sbx rm --force sbxm-spike-s15-same`. **Done when:**
   each point has evidence and `sbx ls` shows no S15 sandbox.
4. **Narrow kit.** Copy the copied `common` kit folder to `H:\sbxm-spike-s15\kits-narrow\common\`, remove
   `setup.install` and set the allow list to `[]` in its `spec.yaml`; `sbx create --name sbxm-spike-s15-narrow` as
   in question 3 but with that `common` kit and the workspace `ws\narrow\`. Record: does it start; is `jq` present;
   does `curl -s -o /dev/null -w '%{http_code}' http://archive.ubuntu.com/` answer 403 (and `sbx policy log` show the
   deny); wall time. Keep this sandbox for questions 5 and 6. **Done when:** each point has evidence.
5. **Pi works from the template.** In `sbxm-spike-s15-narrow`: the `pi -p` question of item 1 answers `MEDLAR-15`
   (the provider secret works and `AGENTS.md` is read). **Done when:** the answer is recorded.
6. **Secrets in the template.** With S11's method (presence only: counts, names, lengths, never a value): search
   `sbxm-spike-s15-narrow`'s environment, process command lines and filesystem (without `/proc`, `/sys`, `/dev`, `/run`
   and the workspace) for the Anthropic key pattern; list what Pi keeps in its home folder (`~/.pi`). **Done when:**
   counts and file names are recorded. Then `sbx rm --force sbxm-spike-s15-narrow`.
7. **Disk.** C: free before and after each create and save; the template's reported size and what it added on
   disk, as in S11's "Disk" table. **Done when:** the numbers are recorded.

## Budget

- One sandbox at a time (`sbx ls` before each create). **Never** while an `sbxm task` batch is running.
- C: must have at least 15 GB free before each create and each save; if not, stop, clean up, report.

## Stop rules

  real sbxm config or profiles, `git` commands that change state, web research beyond `sbx --help` pages.
- New questions go to the results file's Follow-ups list, not into the run.

## Cleanup (always, also after a failure)

1. `sbx rm --force` each of `sbxm-s15-base-pi`, `sbxm-spike-s15-same` and `sbxm-spike-s15-narrow` that `sbx ls`
   still shows.
2. `sbx template rm --force` every tag of `sbxm-spike-s15`.
3. Remove `H:\sbxm-spike-s15\`.
4. Prove it: `sbx ls`, `sbx template ls`, `sbx secret ls` (names) before the spike and after cleanup are the same;
   C: free before and after.
